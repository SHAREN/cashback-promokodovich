# Архитектура

## Поток данных

1. Пользователь присылает кэшбэки текстом или скриншотом.
2. Hermes записывает их в SQLite через `cashback_promokodovich.py`.
3. Для полного набора банка используется полная замена месяца; частичные данные не закрывают банк как заполненный.
4. После изменения реальной базы CLI автоматически публикует актуальный `data.json`.
5. PWA при открытии:
   - мгновенно показывает последнюю локальную копию;
   - затем пытается получить свежий JSON;
   - при успехе обновляет экран и локальную копию;
   - при отсутствии сети продолжает работать с сохранёнными данными.

## Состояние месяца

Для каждого активного банка хранится признак полноты текущего месяца. Он используется Hermes для задач/напоминаний и передаётся в JSON, но веб-интерфейс не показывает служебные подписи вроде «заполнено».

## Ежемесячный цикл

За два дня до нового месяца Hermes создаёт общую задачу собрать кэшбэки. Для незаполненных банков поддерживаются отдельные задачи. После заполнения банка его задача закрывается. Ежедневная синхронизация также публикует данные текущего месяца, поэтому при наступлении нового месяца PWA переключается на него.

## Офлайн-хранение

Используются два слоя:

- `localStorage` — последняя успешная копия `data.json`;
- Cache Storage + Service Worker — оболочка PWA и резервная копия JSON.

При запуске применяется cache-first для интерфейса и local-first для данных, затем фоновое обновление по сети.

## Что не является источником истины

Не следует вручную поддерживать отдельные списки категорий в README, заметках, Kanban или исходниках PWA. Категории должны приходить только из SQLite через опубликованный JSON.
