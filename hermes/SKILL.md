# Cashback Промокодович

Это отдельный структурированный источник данных Hermes для банковских категорий/предложений кэшбэка.

## Source of truth

- CLI: `/home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py`
- SQLite: `/home/renat/.hermes/cashback-promokodovich/cashback.sqlite3`
- PWA: `https://webuirenat.duckdns.org/cashback/` — мобильная страница с текущим месяцем и офлайн-кэшем.
- При изменениях реальной SQLite через CLI `data.json` для PWA публикуется автоматически; `daily-sync` также обновляет публикацию, поэтому на границе нового месяца страница переключается на текущий месяц.
- Не дублировать категории кэшбэка в `USER.md`, `MEMORY.md`, заметках или Kanban-body как источник истины.
- Kanban `life` используется только для ежемесячной человеческой задачи «собрать/заполнить кэшбэки», а сами категории хранятся в SQLite.

## Базовые банки

При инициализации заведены и активны:
- ВТБ
- Альфа-Банк
- Сбербанк
- Ozon Банк

Новые банки добавляются без изменения схемы.

## Когда пользователь присылает кэшбэки

Пользователь может прислать обычный текст или один/несколько скриншотов из банковского приложения.

1. Определи банк. Если название видно на скриншоте/в тексте однозначно, не спрашивай. Если банк новый, добавь его.
2. Определи месяц. При ответе на ежемесячную задачу используй месяц из названия этой задачи. Если месяц явно указан на скриншоте/в сообщении — используй его. В остальных случаях текущий месяц Asia/Yekaterinburg допустим только когда контекст действительно про текущие категории; при реальной неоднозначности задай один короткий вопрос.
3. Для скриншота используй vision и извлеки только видимые факты. Не додумывай проценты, лимиты или условия.
4. Если пользователь прислал полный набор категорий одного банка за месяц, замени набор банка через `replace-json`, чтобы старые категории этого же месяца не остались мусором. `replace-json` одновременно помечает банк полностью заполненным за этот месяц.
5. Если пользователь добавляет/исправляет одну категорию, используй `add`: запись с той же категорией в том же банке/месяце обновится, но банк остаётся незаполненным до явного подтверждения полного набора.
6. Если полный набор был внесён несколькими командами `add`, после проверки выполни `mark-complete --bank BANK --month YYYY-MM`.
7. После записи обязательно прочитай сводку и `missing` по этому месяцу. Если банк стал полностью заполненным, выполни `daily-sync`: связанная Kanban-задача должна закрыться сразу, не дожидаясь следующего утреннего cron.

### Полная замена категорий банка за месяц

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py replace-json \
  --bank "Альфа-Банк" \
  --month 2026-10 \
  --source screenshot \
  --json '[{"category":"АЗС","cashback":"5%"},{"category":"Аптеки","cashback":"7%","limit":"до 1000 ₽"}]'
```

Допустимые поля записи: `category`, `cashback` (или `rate`), `limit`, `conditions`, `note`.

### Одна категория / исправление

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py add \
  --bank "ВТБ" --month 2026-10 --category "Такси" --cashback "10%" \
  --conditions "по выбранной категории" --source manual
```

### Новый банк

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py bank-add "Т-Банк" --alias "тинькофф" --alias "т банк"
```

Если банк больше не нужно учитывать в ежемесячном сборе, не удаляй историю — отключи:

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py bank-disable "Т-Банк"
```

## Как отвечать на запрос списка

Запросы вроде «покажи все кэшбэки», «какие у меня кэшбэки», «Cashback Промокодович», «кэшбэки на октябрь», «что выбрать для покупки X» сначала читают SQLite.

Текущий месяц:

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py list
```

Конкретный месяц:

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py list --month 2026-10
```

Один банк:

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py list --month 2026-10 --bank "Ozon Банк"
```

Какие активные банки ещё не заполнены:

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py missing --month 2026-10
```

При выдаче сводки не скрывай пустые банки: `— не заполнено` полезно, потому что показывает неполноту данных.

## Выбор лучшего кэшбэка для покупки

Если пользователь спрашивает, какой картой выгоднее оплатить конкретную покупку:

1. Прочитай текущую/нужную месячную сводку из SQLite.
2. Сопоставь тип покупки с сохранёнными категориями, но не выдавай неподтверждённое MCC/категорию магазина за факт.
3. Если есть лимиты/условия, учитывай их только если они сохранены.
4. Если несколько банков дают одинаковый результат или категория магазина неоднозначна, кратко укажи это.

## Ежедневные задачи текущего месяца и задача перед новым месяцем

Штатный cron запускает детерминированный скрипт ежедневно в 09:00 Asia/Yekaterinburg.

Каждый запуск сначала синхронизирует **текущий месяц**: для каждого активного банка, который ещё не помечен полностью заполненным, должна существовать отдельная активная Kanban-задача `Заполнить кэшбэки БАНК — МЕСЯЦ`. Эти задачи классифицируются как `anywhere` и находятся в человеческом lane `today`. Частичные данные не закрывают задачу. Когда банк помечен полностью заполненным, соответствующая карточка автоматически закрывается.

Если хотя бы один банк текущего месяца не заполнен, Hermes раз в календарный день отправляет Ренату одно компактное сообщение через `people_reminders.py`, перечисляя **каждый** незаполненный банк. Используется дневной dedupe-key, поэтому повторный cron в тот же день не создаёт дополнительный пинг.

Отдельно сохраняется ранняя задача на следующий месяц: когда локальная дата находится ровно за 2 календарных дня до первого числа следующего месяца, создаётся одна общая Kanban-задача на сбор будущих категорий. Она динамически перечисляет все активные банки из SQLite и не дублируется.

Скрипт:

```bash
python3 /home/renat/.hermes/scripts/cashback_monthly_task.py
```

Диагностика без создания карточки:

```bash
python3 /home/renat/.hermes/cashback-promokodovich/cashback_promokodovich.py task-check --date 2026-09-29 --dry-run --json
```

## Важные правила

- Историю прошлых месяцев не удалять при переходе на новый месяц.
- Не сохранять номера карт, CVV, логины, пароли, полные реквизиты или другие секреты. Для этой базы они не нужны.
- Не считать банк заполненным только потому, что существуют какие-то записи за месяц. Источник истины заполненности — `bank_month_status.complete`: полный набор через `replace-json` ставит его автоматически, а набор, собранный несколькими `add`, требует `mark-complete` после проверки.
- Если пользователь прислал частичный скриншот, не использовать `replace-json` как полный набор; добавляй только подтверждённые категории через `add`, чтобы ежедневная задача продолжала напоминать.
- После любого изменения данных выполнить readback через `list` или `missing` и только после этого говорить, что данные сохранены.
